# 電竜戦出場に向けた今後の予定

11月8日の追加指示により、最良候補の[ShogiHome用パッケージとRelease添付物](shogihome-release.md)を作成した。定跡あり・なしの両方で実86BoxのUSI運用試験と再起動を確認済み。Releaseの公開、ShogiHomeでの実対局、大会時間の全局対局はまだ行っていない。

**完了状況（11月8日確認）：独立4,096局面の測定は11月7日20:57:16 JSTに終了し、20:57:37に集計保存と停止が完了した。基準28.5156%・候補37.6465%、差+9.1309ポイント（対応あり95%区間+7.5439〜+10.7178）、運用異常0。[全件結果](halfkp-development.md)を参照。以下の「現在の測定」は停止指示時点の記録であり、現在は測定も後続対局も実行していない。**

2026年11月7日のユーザー指示により、進行中の独立4,096局面の一致率検証と集計を終えたところで一旦停止する。補助20局・大会時間2局・既定イメージの差し替えは自動実行しない。再開指示を受けてから、以下を順に進める。

## 現在の測定と停止位置

- 固定済みHalfKP幅8・2層のradix版と、新規に起動した駒得基準版を比較中。通常秒読み2秒、NetworkDelay/NetworkDelay2=0、Pentium 100 MHz・RAM 32 MiB、同一4,096局面を使う。モデル・演算・標本を変更しない。
- 11月7日16時台の進捗から、全件終了は本日21:00 JST前後を見込む。実際の探索時間によって前後する。終了後に全件の対応あり比較と95%区間を保存し、測定日時・条件・commit・主な機能差分を含む測定履歴を確認する。
- 事前条件の「差+2ポイント以上・対応あり95%区間の下限が正・運用異常0」による判定を保存する。この判定だけでは本番への反映を行わず、動作検証とユーザーレビューを残す。独立testに合わせた再学習や候補選び直しは行わない。
- 元の実行計画は履歴として保存する。後続対局を起動する親制御だけを保留し、一致率測定は継続している。終了監視は集計後に停止記録を保存する。失敗時も記録を保持して停止し、自動再実行しない。

停止後の結果は`results/2026-11-07/final-heldout-4096-v1-comparison.json`、`final-heldout-4096-v1-adoption-gate.json`、`final-heldout-user-requested-stop-v1.json`で確認する。監視状態は`.local/jobs/halfkp-stop-after-heldout-v1.json`。既定イメージは引き続き駒得版である。

## 再開後の優先順位

1. **全件結果のレビューと出場候補の確認。** 結果・異常・候補manifestを確認する。選択済み候補は`manifests/halfkp-fixed-w8-h0-128m-radix-v1-candidate.json`、起動スクリプトは`.local/profiles/halfkp-fixed-w8-h0-128m-radix-v1/run.sh`。検証するELF・モデル・イメージ・ソースのSHAを固定記録と照合する。
2. **出場候補でUSIと連続運転を確認。** 初期化、評価関数ロード、合法着手、通常時間指定、stop、quit、usinewgame、別プロセスでの再起動、512手の履歴受信を確認する。Threads=1・Hash=2 MiB・RAM=32 MiBで空きメモリとswap使用を記録する。ホスト実測とエンジンの時計のずれも確認する。既存の候補確認結果を参照し、出場経路に必要なチェックを実施する。
3. **ShogiHomeの実際の接続経路を確認。** 新候補のUSI起動スクリプトを登録して初期化・対局開始・着手・終了・連続対局を確認する。従来の「3分2秒で2局成功」は旧構成の実績であり、新候補の確認とは区別する。
4. **大会条件で2局の動作確認。** 平手から候補と基準の先後を入れ替える。先手3分、後手10分、双方1手2秒加算、`MaxMovesToDraw=512`、入玉27点法。実対局では環境に適した`NetworkDelay`/`NetworkDelay2`を指定し、値と時計実測を記録する（既存計画の開始値は120/1120 ms）。ブリッジによる持ち時間の書き換えは行わない。切断・反則・時間切れ・時計更新・終了処理を確認する。非対称時間のため、この2局をElo推定には使わない。必要に応じてShogiHomeでの人手確認を組み合わせる。
5. **本番構成を固定。** 採用条件と動作確認を満たした構成について、現在の既定イメージをSHA付きでバックアップし、検証済みの同一イメージを反映する。実際の既定起動経路でUSI・再起動を確認し、大会設定・起動方法・SHA・復旧手順を保存する。測定履歴と手順書を更新してcommitする。
6. **余裕ができてから棋力測定を補完。** 固定10開始局面を先後入れ替えた20局（双方3分+2秒）の補助対局とレーティング推定は後回しにする。必要なら改めて実行予定を決める。今回の一致率終了後には起動しない。

## ユーザーが手作業で行うこと

停止後に全件結果と上の再開順序をレビューし、再開を指示する。ShogiHomeでの新候補の登録・接続確認・実際の対局操作はユーザーの画面で行う。再開時に登録する起動コマンドと設定値を提示する。現時点で設定変更を行う必要はない。

## 別セッションからの結果回収

評価はsystemd等のサービスではなく、Codex実行基盤から起動したプロセスである。評価本体は`start_new_session=True`で独立したOSセッションを持つが、実行基盤による終了処理からの独立までは保証しない。実行基盤やホストを終了させないこと。停止中の元の制御親を手動で再開・終了しないこと。

この会話での応答やポーリングは不要で、評価と集計監視は自律的に進む。同じマシン・同じリポジトリを参照できれば、別の会話・端末から結果を回収できる。会話画面を閉じる操作によって実行基盤がジョブを終了するかは未確認のため、閉じても継続するとは保証しない。
