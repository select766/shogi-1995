# GNU Shogi 対ランダム合法手の実験

## 結果

2026-11-17にGNU Shogi 1.2p03のネイティブ版を、合法手を一様ランダムに選ぶ相手と平手初期局面から200局対戦させた。GNUは先手100局・後手100局のいずれも勝ち、引分・打切り・異常終了はなかった。全200局で敗者に合法手がなく、その最終局面は王手だった。平均52.38手、最短11手、最長104手。成りは542回、駒打ちは797回あった。

これはこの条件での結果であり、あらゆるランダムな手順への必勝の証明ではない。ランダム側は駒や移動先を先に選ぶのではなく、`cshogi.Board.legal_moves` が列挙する手を等確率で選ぶ。先後は交互、Pythonの疑似乱数の種は `20261117`、最大512手、千日手は既存の対局判定器で扱った。GNUは定跡なし、`go depth 2`、時間切れによる負けなし。以前のやねうら王との10秒／手の対局とは条件が異なる。

[全棋譜・GNUの各探索結果](../results/gnu-random-2026-11-17/games.json)を保存した。`gnu_side` と `winner` は先手0、後手1。`thinks` の `actual` はGNUの応手、`host_ms` などの時間は測定環境に依存する。棋譜には投了などの盤面を変えない応答は含めない。この実験では全局が合法手なしで終了した。

## 局面の照合と限界

ホストの `cshogi` が合法手の列挙と判定を行う。GNUの[USI中継器](../historical/usi.py)はGNUの思考前に初期局面から棋譜を再構築し、GNU側から読み戻した盤上の駒・持ち駒・手番・手数をホスト側と照合する。GNUの出力手も合法性を検査する。200局でGNUが思考した5,288局面の照合はエラーなく通過した。終局後には再度GNUに局面を送っていない。

保存棋譜の再生では、手ごとの合法性、乱数列に基づく相手の選択、GNUの探索結果と棋譜の一致、終局理由、最終局面の王手を確認する。ただし、読み戻しの照合先と再生時の合法性判定はともに `cshogi` に依存するため、独立したルール実装による検証ではない。記録には実験中の盤面読戻しログを含まず、その照合が通過したという実行結果と棋譜を保存している。全局面の解釈の正しさを証明するものではない。

## 再現と検証

リポジトリルートで実行する。[構築手順](../historical/README.md)に従って依存物とPython環境を準備し、`bash historical/build-native.sh` でネイティブ版を構築する。既にバイナリがある場合、同スクリプトは上書きしない。オリジナルの測定バイナリのSHA-256は `dabd529e07ba91a66b69abbbbe2476ea358fd125fc3ec331346e45cea7c2e5b9`。コンパイラ等によって再構築したバイナリや棋譜は変わり得る。元のバイナリのコンパイラ版は今回の記録から特定できない。ソースアーカイブのSHA-256は `3e30ef3457dc676f58868a3078dc6ab6e6f5c7058eccd87b14a813fcc000c6b3`、互換パッチは `bd8b511a1dac5f5073447ff23db45f1d6156a38080dbf7558e8f901452294306`。

```bash
# 新規ディレクトリを指定。既存ディレクトリは上書きしない。
.local/venv/bin/python historical/random-match.py \
  --output .local/random-match-reproduction --games 200 --seed 20261117 --depth 2 --max-plies 512
.local/venv/bin/python historical/verify-random-match.py .local/random-match-reproduction/results.json

# 保存した元の実験結果の検証
.local/venv/bin/python historical/verify-random-match.py results/gnu-random-2026-11-17/games.json
```

実験時の小さなスクリプトを整理して `random-match.py` として収録した。対局手順と乱数の使用方法は同じで、出力先や条件を指定できる。各局の完了時に結果を保存し、エラー時は例外も記録する。出力ディレクトリにはUSI通信ログとGNU側の実行ログも残る。`cshogi==1.1.0` は `requirements-evaluation.txt` に固定されている。再現時に全く同じ棋譜を得るには、エンジンのビルドだけでなくPythonや合法手の列挙順なども影響し得る。
