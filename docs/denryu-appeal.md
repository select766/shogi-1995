# 文部科学大臣杯第7回世界将棋AI電竜戦本戦 参加ソフト「1995」 アピール文書

2026年11月12日
作者: select766

## コンセプト

1995年のパソコンで、最新の将棋ソフトを動作させたらどれぐらい強いのか？という問いを検証します。現代のアルゴリズム・評価関数学習データ・定跡を活用し、生成AIの力でまとめあげました。

GIGAZINEの記事「[現代のチェスAIを動かす30年前のPCと昔のチェスAIを動かす現代PCが対決、100局の勝敗は？](https://gigazine.net/news/20261104-modern-chess-engine-vs-pc/)」に触発されて開発しました。

## ソフトの内容

[やねうら王](https://github.com/yaneurao/YaneuraOu)を、1995年当時のパソコン環境を再現したエミュレータ86Boxで動作するように移植しました。CPUはPentium 100 MHz、RAMは32 MiB、OSはSlackware 3.0（Linux 1.2.13）です。

移植にはOpenAIのCodexを活用し、ほぼ全自動で実施しました。1995年当時のC++コンパイラではやねうら王をビルドできないため、GCC 11.2.1のi486向けクロスツールチェーンを使い、Pentium向けにクロスコンパイルしました。 エンジンを単一スレッド化し、メモリ使用量を削減するとともに、旧Linux用の起動コードとシステムコール互換層を実装しました。

評価関数には、独自に学習した幅8・重み2層の小型HalfKP NNUEを用います。ネットワークの重みとバイアスは約100万個です。たぬきチームが提供する[局面データセット tanuki-.nnue-pytorch-2024-07-30.1](https://huggingface.co/datasets/nodchip/tanuki-.nnue-pytorch-2024-07-30.1)を、qsearchやシャッフルなどで前処理し、教師あり学習しました。

定跡は、[やねうら王プロジェクトのFANBOX](https://yaneurao.fanbox.cc/)で提供された新ペタショック定跡を編集して用いました。そのままではエミュレータのディスク（504 MiB）に入り切らないため、先手・後手に分けて、それぞれ自分の手番では原則として評価値が最も高い1手だけを残し、相手の合法手を展開する形でサイズを削減しました。先手の初手は2六歩に指定しています。

対局サーバとの通信は、86BoxのCOM1を使ったシリアル通信により、ホスト（現代のパソコン）側のShogiHomeを介して行います。


## ソフトの性能

floodgateでのレートは約2800でした。また、1995年のGNU Shogiを現代のパソコン(Ryzen 7 5700X)で動作させて比較したところ、エミュレータ上で動作するやねうら王が100戦中100勝しました。両者とも定跡なし、1手10秒の指定で、50の開始局面から先後を入れ替えて対局した結果です。この条件では、ソフトウェアの進歩が計算機性能の差を上回りました。

評価関数として「[つようら王11mini/micro](https://yaneurao.fanbox.cc/posts/12761272)」が動作するように移植することも試みましたが、計算負荷が高すぎて約360 NPS(node per second)しか出ず、先述の独自に学習した評価関数（約7000 NPS）のほうが棋力が高いようでした。計算機性能に合わせて適切な規模の評価関数を使用することが重要であると言えます。

より詳細な実装内容は、2026年11月21日からの[技術書典](https://techbookfest.org/organization/29050048)で頒布予定です。
